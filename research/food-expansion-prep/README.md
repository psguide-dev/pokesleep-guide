# 食材収集力評価の段階別拡張

v627は通常計算58種、v628は回復25種を加えた83種を対象にする。共通日産エンジンを使用する。元の拡張準備資料の56種に、現行データのタマゲタケ・モロバレルを加えた。進化前・サイズ違いは別IDで扱う。

- 登録台帳87種：通常計算58種、回復25種、特殊4種。
- 58種のLv60/70/80の1032条件に、回復25種の450条件を追加する。合計1482条件。
- 評価の初期値はLv80（予測）。60/70も選択できる。将来サブスキルが未設定なら未判定。
- 料理・食材構成の環境適性は別軸として設計中。このデータには混ぜない。
- 特殊4種は未接続。全87種対応とはしない。回復は単体への収集増のみ。5体編成での対象抽選やチーム貢献は評価しない。

## 生成

`inventory.cjs`で現行カタログとエンジンの指紋を記録する。`PSN_REFERENCE_COMMIT`に照合済みのソースコミットSHAを渡せる。未指定ならローカルHEADを記録する。指紋はカタログ・本番の日産ソース・補正・特殊スキルエンジンを含む。

`generate.cjs --species <IDをカンマ区切り> --levels 60,70,80 --output research/food-expansion-prep/output --resume`

暗黙の全種生成は拒否する。種類×レベル単位で保存し、指紋が一致した結果だけ再利用する。通常計算対象をIDで明示選択して実行する。異なる種類の生成は並列実行できる。

`assemble.cjs direct`または`assemble.cjs recovery`は指定した段階の対象がそろい、指紋・条件・構成数が一致する場合だけ公開用の3ファイルを作る。途中結果は公開しない。公開データは`assets/evaluation/food_direct_v3_{60,70,80}.json`と`food_recovery_v4_{60,70,80}.json`。

## 検証

`node tests/check_food_expansion.cjs`で全1482条件の理想100%再現、姿別対象識別、未設定入力、登録値の不変性、エンジン指紋、元の3種54条件との完全一致、分割ファイル読み込み・失敗後の再読込を確認する。

`node tests/check_food_role.cjs`は既存の固定構成・日産合計・詳細比較・将来未設定・きのみS単独無効の回帰検証を維持する。

`node tests/check_food_recovery.cjs`で全25種の回復OFF比較と自己・全体・対象回復の単体への反映、スキル確率だけを変えた比較を確認する。回復種の同値統合キーは発動率を含む。
